# 第四轮：时变通行窗口与有界SIPP

本实现仅面向参数化吊装和分段直线飞行的合成软件仿真。原保守占用继续可切换，独立复核始终保留。不宣称原始SIPP在本工程的有限图、资源标签、离散包络、有限地面等待候选和预算截断后仍具有全部最优性或完备性。

## 接口与四类占用

`world.planning_policy.mode`取`conservative`（缺省）或`dynamic_windows`。示例输入可放在`observed_snapshot.planning_policy`。动态模式另外接受`max_time_step_s`（默认1，上限5）、`max_cell_inflation_m`（默认0.25，上限5）和`max_cells`（默认30000，范围1–200000）。错误模式、无效数值返回不支持/不完整状态。

- 塔身等设施物理占用在确认完成后仍存在；只有拆除确认才能解除。
- 物理部件随吊臂回转、吊物升降、暂停、恢复和连续停车改变位置。
- `activity_policy=recorded_envelope`的活动包络在完整生效区间内持续禁入。动态几何出现空隙不解除这条规则，计划结束也不解除它。
- 只有显式`moving_components_with_clearance`的作业保护跟随运动部件；活动余量、设备误差、飞行器保护半径分别施加一次。策略选择不是运行许可或现场授权。

`motion_model.uncertainty_bounds`为：

```json
{"position_m":0.0,"clock_s":0.0,"source_ids":["record_initial"]}
```

零值在本示例中表示明确的合成规则假设，不是实际测量精度。`position_m`是设备部件位置误差的各向同性米制界；`clock_s`是设备运动程序相位误差，按部件速度界转为空间膨胀，不是事件到达时间、计划结束时间或完成确认误差。引用必须属于该运动参数的来源。真实记录没有这些界时不能默认精确：动态搜索为相应约束退回完整范围，记录`conservative_fallback_missing_uncertainty_bounds`。旧round3分析器仍允许按声明的确定性规则进行条件性分析；这不意味着缺失误差已被校准。

已知姿态的误差膨胀为`position_m + V × clock_s`。相位误差窗口碰到未知姿态区间时改用完整范围包络；时间切点同时包含相位误差前后的程序/命令边界。未知停车、未知程序外姿态继续占用范围。分析与独立参考使用同一误差契约；独立参考的碰撞算法没有调用规划窗口或主检查的相交函数。

## 连续整航段窗口

`temporal_windows.py`对每条动态约束构造时间管。片段`[a,b]`的设备中点几何，增加`V(b−a)/2`，包含片内所有设备位置。时间片切于程序、暂停/恢复、完成/停车、模型版本及相关误差边界。速度界与round3模型相同：塔身0，臂长×角速度，索/物为吊点幅度×角速度＋最大升降速度。

若航段持续`T`秒，其空间参数区间`[u0,u1]`与某一时间管相交，则禁止出发区间包含`[a−u1T, b−u0T]`。对全部约束取并集，再取补集得到可用出发窗口。这检查整条航段的全部通过过程；不能因起终节点可用而放行中间碰撞。节点安全区间是同一时间管的点占用补集，并叠加其他飞行器连续运动和资源预约。

该方法有意保守：忽略时间片内几何与飞行进度的更精细相关性，可拒绝实际可行通行。规划还加入`2 × 模型max_cell_inflation_m`的数值复核余量，消除主分析器在不同航段切片位置构造较宽包络造成的边缘不一致；这一额外搜索余量单独输出为`independent_partition_review_guard_m`，不删改业务约束或降低复核要求。动部件才需要该余量，静止塔身为0。时间边界留`1e-6`秒保守余量，空间接触视为冲突。

时间管有总处理预算和搜索截止时间；超限返回`search_budget_exhausted`或`search_timeout`，不会释放半成品窗口，也不会称为全局不可行。几何/运动缺失仍返回明确状态。位置筛选只剔除确定不相交的外包围盒，未筛掉项仍进行整段求交。

## 等待、资源和缓存

搜索维持原任务的服务位置、时长、顺序、时间窗、期限和能量上限。动态模式从原航段禁止出发窗口的边界播种最多64个额外地面延后标签，避免只允许早起飞后悬停造成不必要的能量失败；不保证这个有限集合涵盖全部等待策略。地面等待必须从实际原起点连续占用允许等待的起降点，没有自动插入场外等候或瞬时入场。

空中等待是在已检查的节点安全区间内保持位置、占用空间预约并消耗显式线性能量。当前简化模型不含专门空中等待区容量、风场或机体动力学。地面起降点容量与飞行器物理分离分别检查；容量大于1不会消除同位置保护体相撞。修复了旧节点安全区间按“任意预约即占满”处理容量的错误。

在途搜索仍使用实际模拟位置、时间和剩余能量；已执行前缀经`execution`恢复后由完整复核再次核对，不能直接回起点。候选建议与现行计划保持分离。

缓存为进程内有界LRU（最多16组时间管）。键包含环境、规则、模型、情景、知识时刻、时域、完整约束/任务/预约/资源和策略指纹。事件、误差、任务或预约变化产生新键，旧内容不会错误复用。没有把未到达事件放入键或窗口。候选搜索输出只含确定性配置/指纹/检查信息，不将缓存命中和计时等易变值写进相同候选内容。

`search_task`返回`planning_mode`、`temporal_windows`和成功时的`planning_explanation`。后者列出实际航段时刻、整个航段的允许出发窗口、等待位置/资源/能耗、服务要求、持续禁入和回退约束。显示的对象出发窗口不等于全部资源窗口；飞行器相遇与起降预约还经过独立连续检查。

## 可重复手算样例

```bash
.venv/bin/chengkong analyze --input examples/round4/dynamic_window.json \
  --scenario dynamic_window --as-of 0 --output runs/round4/dynamic-window.json
.venv/bin/python -m unittest discover -s tests -p 'test_dynamic_planning.py' -v
```

样例为100×100米局部园区。航路沿`y=60,z=10`，从`x=10`到`90`；吊塔基点`(50,50,0)`，吊点幅度10米。初始角90°时，吊索位于`x=50,y=60,z∈[5,20]`。程序0–20秒保持，20–40秒回转至0°；任务2秒起飞、5秒爬升、10米/秒平飞，因此原航段在11秒到达吊索。起终节点都安全，整航段仍冲突，这个结论可直接计算。

12项新专项实际通过（3.323秒，测试数量不代表运行收益），另旧motion13项和planning7项通过。覆盖：

1. 保守全范围直接路线无结果；动态模式地面等待后直接通过，保持服务且主检查/独立参考通过。当前样例实际起飞17.2166359106秒、结束37.2166359106秒，地面等待15.2166359106秒。
2. 相同几何将期限设30秒、服务窗止25秒：等待不可行，绕行22.0085456263秒完成，没有修改任务要求。
3. 全时活动禁入或吊索始终保持横截：直接搜索无结果，不标全局不可行。
4. 新增3秒相位误差记录：旧版本候选失效，原路径在新误差约束下冲突。
5. 两架飞机明确同时占用同一个容量1等待点：第二个搜索返回`initial_pad_unavailable`，不会编造场外位置。
6. 两个节点全时可用，但7秒出发的整航段被禁止，独立参考检出11秒附近穿越。
7. 吊物升降也实际改变搜索窗口；暂停保持仍占用，完成后4个物理部件仍在。
8. 8秒在途维护保留`(20,60,10)`前缀末点及全部已执行轨迹，经独立复核后产生绕行候选。
9. 明确误差来源、有限预算、缓存版本变化、重复结果一致性，以及容量与物理分离的区别。

全部为合成规则下的软件检查。任意坐标转换、吊物复杂摆动、变幅、真实动力学、遥测/飞控、现场效果和全局最优证明仍未实现。
