# 第四轮学习与运行评估

本轮不重新训练模型。round3的敏感性、GNN和候选排序权重均只读保留；它们仍承担检查顺序、任务处理顺序和候选动作顺序三个不同任务，不提供约束放行依据。精细吊装、同机连续任务和完整事件序列超出其训练域，本轮标为`out_of_domain_unvalidated_sequence_and_motion`。规则继续默认，旧单变量校准的覆盖率不外推到新事件分布。

## 诊断先于模型扩充

旧联合对照的12事件来自6模板，44是任务出现次数。`tasks_completed`旧字段实际是“有完整复核通过的联合候选时计入该事件全部任务数，否则0”；14/44不是实际飞行完成14项，余下30也不是分别证明不可行。固定3bcf1bd源码归档重新执行得到同样5/12。

7个失败事件中4个含未解析活动几何。另有几何清晰任务因能耗超限未加入修复集，直到最终复核才被拒绝；本轮已修复这项候选遗漏。部分任务的必达服务和既定垂直起降/定高巡航模型已经要求超过容量的最小能量。共享起点的任务在固定入场时刻下也可能必然争用起降容量。提高搜索预算无法补足这些信息或改变任务要求。没有通过放宽保护、增加期限、删除服务或提升电池参数提高旧结果，修复后仍5/12。

独立算术脚本`reference_round4.py`不导入规划器，给出服务距离/速度/服务时长/保留电量下界及起降点最小占用重叠。它只证明**明确的现有航路类别和入场模型内**的必要条件失败，不证明任意飞行动力学下全局不可行。3个信息完整失败事件还运行96次顺序/512次搜索/20000展开/8秒高预算，未找到候选；无结果依然不作为不可行证明。

序列pilot发现另一真实衔接问题：地面等待时已经形成冻结前缀，后续起飞时刻仍是未来；新后缀改变起飞时刻后，完整计划沿用了旧起飞/等待元数据。现按拼接后的完整轨迹重新派生元数据，冻结前缀不变。修复前pilot动态两次独立复核拒绝，修复后同输入拒绝为0。上述问题主要在规划/执行衔接与数据范围，不是网络容量；小样本上继续训练会掩盖主要问题。

## 协议错误、纠正及保留记录

初稿把同一个`dynamic_window`基础拓扑的24个随机参数组误称24个独立模板，并分到不同集合。这不符合按基础模板及派生关系隔离的要求。根审查指出后，没有删除原数据、pilot或第一次已观察结果：`round4/protocol-correction.json`明确旧独立模板计数无效，旧`sequences/`与`evaluation/`仅保留为**一个基础拓扑的参数扰动诊断**，不能作为独立泛化证据。该批结果没有用于调整模型或规则。

纠正后的`topology_sequences/`包含3个人工定义的不同父拓扑，每个2个参数/到达事件变体，共6条完整序列、24次决策：

- 折线航路与两个必达服务节点；
- 双施工点、四个起降点和交叉任务走廊；
- 三起降点闭环、同一飞行器三项连续任务。

全部派生只在test组；本轮训练、验证、校准组均为0，因为没有再拟合或选型。父拓扑、完整输入SHA256与到达顺序在新测试前保存于`protocol-frozen.json`和`data-manifest.json`。这只有3个人工合成父拓扑，不能当作6个独立模板、24个独立事件或真实现场随机样本。不报告不适当的显著性或总体安全概率。共享起点/等待区容量的证据来自专项与旧参数诊断，新3拓扑测试不被描述为覆盖全部六种旧模式。

真实将来的施工记录只由仿真外层持有，每个决策按`observed_at_s`释放，模型与规划器只收到当时可见world。已知运动规则可以用于预测窗口；它不是未到达完成事件。任务保持完整服务、窗口、容量和版本，已执行轨迹前缀不能回写。

## 公平对照和计时

主方案在新测试前固定为保守占用规则、动态窗口规则、固定keep→detour→delay规则、round3学习排序。另保留round3训练过的同节点特征无边网络对照；节点度等关系汇总仍在，因此它比较消息传播增量，不代表删除所有图信息。每个方案使用相同可见材料、任务要求、候选动作和复核，动态方案只有处理顺序不同。keep先通过同一个完整现行计划复核，不把有冲突的keep当作免检候选。

每次有共同2秒候选决策预算，包含world更新、约束、特征、推理、初始检查、现行计划复核、搜索和候选复核。特征/推理等已用时间从剩余搜索额度扣除；最多8个顺序、32次搜索、2500展开。超过截止才完成的候选不计入预算内成功或采纳；保守计算不能为了满足秒数跳过强制复核，实际超额单列。补证统计、SQLite事务和结果导出在决策后另外计时，总开销也保留。模型加载一次以及无边适配器加载另列，暖态时延不冒称冷启动耗时。

高预算参考按两个不同父拓扑各选一个变体，最多48顺序/128搜索/15000展开、每决定6秒，并用累计120秒墙钟闹钟限制；完整评价总预算900秒，每次决策检查剩余预算并保留检查点。高预算结果仅是已知可行参考或仍未找到，不称最优真值。

独立源码快照避免开发过程改变执行版本。第一次新拓扑运行与QA重叠，且新加入候选内的运行耗时字段导致Web相同候选ID内容变化；该记录保留但不作为主运行时效证据。修复将耗时移至diagnostic summary，候选内容保持确定性。纠错后的固定源码复现显式记录旧/新代码hash与原因，原selection、输入、模型和首次结果不覆盖，不把复现宣称为新的盲测。

## 指标解释

`joint_feasible_decisions`是当次时间预算内存在满足未来维护要求的完整候选；在途历史冲突仍独立记录，不会被这个成功字段抹除。`joint_plan_covered_task_occurrences`在这些决定中累计完整任务集合，分母为各决定任务出现次数。软件执行指标另列截至末次证据到达时已经结束、完整几何/服务/资源检查通过的任务；已结束但历史不合格与仍在计划中的任务分开，不称真实飞行完成率。

多次采纳用真实`PlanStore.adopt(..., explicit=True)`，在独立临时SQLite运行。每个方案采用相同且明确的`simulation_adoption_policy`：完整复核通过的现行计划继续保持；仅现行未来计划失效且存在合格候选才模拟采纳。它不启用Web自动采纳。每任务修改次数、重复修改、累计延误/路径/能量均保存。

共同成功集合的主要代价相对**共同初始计划**累计，并同时报告绝对路径长度、能量及到达时间。不能把各自分叉后的incumbent当作统一基线，让后续keep代价都变成0。原始每步增量代价仍保留，便于检查修改过程。

补证请求与实际查询状态、等待秒数有记录，但确认来自预先固定、按到达时刻释放的合成记录。这里没有试验查询策略改变证据到达的因果作用；待证秒数不是额外飞行延误，查询未知也不改变世界。新序列不拟合结束误差校准，也没有新覆盖率保证。
