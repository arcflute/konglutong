# 城空智护：项目说明

## 定位

“城空智护”面向城市施工环境变化，将设施状态与作业信息转化为时空约束，分析对既有低空任务的影响，形成兼顾风险约束和计划稳定性的航路维护建议。

参赛方向：第十二届中国研究生智慧城市技术与创意设计大赛，定向赛道“低空经济与空天科技”。队伍：城空知变队。团队来自武汉大学地球与空间科学技术学院、国防科技大学数学学院、哈尔滨工业大学计算机学院及复旦大学计算与智能创新学院。赛事题目与要求以用户提供材料及后续核实的官方文本为准，本文件不宣称完成参赛资格或提交要求核验。

## 贯穿场景

某园区已有巡检航路，附近施工点新增吊装作业。设施高度与活动范围发生变化，作业结束时间可能延期，需要重新判断原有任务是否受影响，并比较保留原计划、延后、局部绕行及暂缓任务等方案。

这是一项项目设定场景，不包装成已经发生的事故、现场调研或已部署案例。

## 目标使用者与工作流

目标使用者为园区低空任务运营人员，以及负责施工信息维护的管理人员。

1. 导入园区几何、设施资料、施工记录及原始任务。
2. 校对结构化字段、来源、有效时间和未知信息。
3. 更新场景状态并推演按期、延期、未确认等情景。
4. 查看受影响任务、冲突位置、时段、原因及证据。
5. 查看必要的补证请求；有新证据时更新后重算，无证据时保留不确定性。
6. 比较航路维护候选及其变更代价。
7. 在条件与版本复核通过后，由用户采纳候选，更新当前计划与占用记录。
8. 回放施工变化和计划调整过程，展示未解决问题及模型适用范围。

## 三个问题

- 变化信息难转化：施工记录描述设施和作业，飞行计划描述航段和通过时间，需要建立语义与时空对应。
- 影响判断不确定：位置、高度、作业时段、结束确认和更新状态可能缺失或滞后。
- 调整存在代价：延后、绕行和保守限制都会影响运行，应同时考虑约束满足与计划稳定性。

## 当前约束

- 软件开发为主；无法现场调研。真实数据后续从网上获取并核对许可、时效与适用性。
- 允许明确标注的合成数据用于开发、联调和仿真；不能据此声称真实部署效果。
- 保留三层技术设计，分阶段实现。没有必要新增第四个核心算法层；数据接入、事件日志、展示、采纳和回放作为公共集成能力。
- 初期采用参数化设施、规则推演、确定性冲突计算和图搜索；学习模块后续用任务匹配的数据训练，VLM 可采用外部 API。
- 已讨论的服务器配置可作为规划参考，但开发环境与可用资源须在目标机器重新检查。
- 系统产出条件化的辅助维护建议，不直接下发飞行器控制指令，不声明已获得现实空域许可或工程安全认证。

## 展示内容

同一场景下展示施工变化前后、受影响与未受影响任务、冲突证据、补证过程、候选方案差异、采纳后的计划版本及事件回放。页面展示的数据应可追溯到后端真实计算或明确标注的示例来源。
