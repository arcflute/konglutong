# 空路通桌面 v1.1 三端演示

所有输入为明确合成资料；没有真实飞行、审批或外部消息。每次从**新的db-dir**开始，避免上一演示已采纳路径改变后续判断。先按[实施说明](FRONTEND_IMPLEMENTATION.md)构建前端，服务由Python提供，浏览器通过本地/SSH访问。

## A 企业维护，并向政府展示同一事件

```bash
.venv/bin/chengkong serve --input examples/frontend-v1/park.json \
  --db-dir runs/frontend-v1/demo-A-001 --host 127.0.0.1 --port 8765 \
  --demo-identities --action-policy keep_detour \
  --model-dir /root/autodl-tmp/chengkong-models/round3
```

1. 门户进入企业端，选择“林工”，场景“结束待确认”。总览读取当前t+60、环境/预约/计划版本及真实任务。进入航路维护，先查看候选与独立复核，暂不采纳。
2. “变化与证据”→“导入结构化材料”→“载入合成延期模板”→“解析与校验”。逐字段查看实体、来源、有效/到达时间、计划时段和提议ID。
3. 点击“明确接受有效更新”。环境更新、原任务暂不自动替换，补证与分析重新计算。回到“航路维护”，勾选“含历史候选”，旧候选显示失效、按钮禁用；直接调用同ID采纳也由服务器拒绝。
4. 取消历史筛选，选择当前复核通过候选；地图叠加原计划和修改部分，查看延误/距离/能耗、变更任务、适用条件与未解决信息。点击“查看并确认采纳”并在弹窗明确提交。只有实际成功后才显示采纳结果；总览、任务/预约和版本刷新。
5. “回放与报告”选过去快照，再返回当前；当前计划不变。生成报告，预览/JSON下载/打开打印报告。浏览器“另存为PDF”是本地打印，不发送外部服务。
6. 顶部切换研判员身份（或回门户），进入政府台账。同一已到达施工变化保留对应环境版本，只显示获准共享任务；填写核查意见并刷新，备注保留，施工事实不被核查文字修改。政府不能采纳企业候选。专题报告生成授权范围快照。

实际验收：旧候选拒绝、新候选明确采纳，原计划/预约版本同步，JSON与预览快照一致，真实PDF已保存。证据：`browser-verified/A-*`、`stale-rejection.json`、`enterprise-report.json/pdf`。核心场景分母为当前本机构3任务，政府只共享2任务，不是全市数据。

## B 字段补证改变判断，但保留设施

停止A后，用独立目录重新启动：

```bash
.venv/bin/chengkong serve --input examples/frontend-v1/park.json \
  --db-dir runs/frontend-v1/demo-B-001 --host 127.0.0.1 --port 8765 \
  --demo-identities --action-policy keep_detour
```

1. 企业端选择“结束待确认”，顶部“仿真控制”推进到t+360。先在“影响分析”查看task_2冲突。
2. “变化与证据”查询 `lifting_1` 的“完成状态”，没有对应材料时返回未知，不把计划结束当作确认。
3. 打开结构化导入，上传 `examples/frontend-v1/completion.json`，或粘贴其完整JSON。该文件明确为虚构完成记录，有效/到达时间均360，来源定位可核对。
4. 解析、检查提取值和元数据、明确接受，后端第一层确认完成并重新分析。实际task_2对象冲突变为本次范围未发现冲突；塔吊物理占用仍存在，必须独立拆除证据才能结束设施占用。
5. 到航路维护查看当前候选与条件；环境更新不自动等于采纳。回放可看到更新前后知识状态与版本，导出保留来源。

实际证据：`browser-verified/B-unknown-preserved.png`、`B-completion-keeps-facility.png`及报告请求轨迹。此结论基于静态park输入；不要在已绕行的A库或不同运动参数库上要求同一task_2变化。使用无材料的未知状态不会制造有利证据。

## C 个人关注、提醒与跨端状态及重启

```bash
.venv/bin/chengkong serve --input examples/frontend-v1/park.json \
  --db-dir runs/frontend-v1/demo-C-001 --host 127.0.0.1 --port 8765 \
  --demo-identities --action-policy keep_detour
```

1. 门户选择个人端“陈同学”，场景“结束待确认”。公开地图没有企业航路/候选成本；点击“关注此区域”。航前环境提示查询60–600秒，保存本人查询。
2. 切换企业身份，按A的模板导入并明确接受延期。该活动预先获准公开，状态变化产生独立公开版本；新的任意材料/对象不会自动公开。
3. 切回陈同学→“关注与提醒”，出现一条公开变化通知。刷新不重复生成，标为已读；“记录与反馈”提交线索，返回持久ID和“已收到·待处理”，不直接更新世界。
4. 切换“李同学”或其他机构，不能看到陈同学记录或本机构任务。再切回原身份，记录仍在。
5. 可在政府“城市变化台账”展开“公开摘要”，输入依据并“撤下公开摘要”。回个人提醒显示已撤下且无详情；保存查询中的对应详情也被服务端过滤。独立获准公开的塔吊物理实体仍显示。政府可恢复同一原批准摘要，不能发布任意新私有对象。
6. Ctrl+C正常停服，以**原命令、原输入/模型/代码/目录**重启，再打开浏览器。关注、已读、反馈、已采纳计划、事件位置和历史保留。过期会话需重新选择演示身份，记录归属不变。

实际证据：`browser-verified/C-*`及其重启强断言，`browser-edges-verified/public-revocation-audit.png`、`revoked-inbox-hides-details.png`。另有三独立进程、备份/恢复强断言，见 `recovery-process/result.json`。

## 运动与在途补充演示

采用 `examples/frontend-v1/motion.json` 和新目录启动。企业影响分析/航路维护或政府态势的“运动预览”滑块移到180秒，后端生成回转臂、索、吊物和活动保护；显示“当前知识的规则预览”。它不推进当前t+60时钟、不提前释放完成证据。全时禁入与运动间隙语义仍由原求解器决定。

企业“仿真控制”推进到120，再在影响分析的高级选项勾选冻结前缀重新分析；候选保留后端计算的已执行轨迹。可显式启用学习实验并运行规则/学习对照，当前模型版本、范围外状态和实际结果如实显示。规则仍为默认，学习不是硬约束通过依据。本轮未重训模型，也未证明学习优于强规则。

浏览器自动复现命令见[验收记录](FRONTEND_ACCEPTANCE.md)。所有导出、版本和候选ID以实际运行结果为准，重复演示不要手工填固定“成功”或预期统计。
