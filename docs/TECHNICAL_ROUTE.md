# 城空智护：三层技术路线工程整理版

状态：完整设计依据；当前已经实现的基线、合成训练与未完成方法逐项见 `FEATURE_MATRIX.md`，本路线文本本身不代表全部实现或验证。本文根据已确认的会话方案整理，用于把论文式方法转为工程任务；不是用户本地最终版 3.2 的逐字原文。拿到 `docs/source/` 中标明最终版的原稿后，先对照差异再更新本文件，保留原稿。

## 0. 三层关系及公共约定

第一层维护“当前知道什么、来源是什么、未来有哪些情景”；第二层把施工语义转成动态约束，分析任务与约束冲突；第三层在约束下维护既有计划，并把候选提交第二层复核。补证结果回到第一层，形成状态更新后再向下游传播。

不新增第四个核心算法层。数据接入、持久化、事件版本、界面、采纳反馈与仿真回放属于公共工程能力。

### 0.1 不同图结构

| 图 | 作用 | 主要元素 |
|---|---|---|
| 语义场景图 | 表达设施、作业与证据关系 | 建筑、设施、活动、记录及关系 |
| 任务—约束关联图 | 筛选受影响任务、表达共同成因 | 任务节点、约束节点和时空关联 |
| 航路图 | 进行时空搜索 | 航点、可通行航段、耗时与资源属性 |
| 联合修复关系 | 识别需要共同维护的任务 | 共享约束、航段、起降资源或飞行器的任务 |

它们通过稳定 ID 与版本关联，不能以一个含义不清的“知识图谱”代替全部计算。

### 0.2 通用数据契约

空间量写明单位、坐标系与高度基准；初期可使用明确标注的局部米制坐标。局部 z、海拔和离地高度不能直接混用。时间写明时区或模拟时间原点；时段建议采用半开区间 `[start,end)`，连续几何边界接触是否算冲突及数值容差须统一并测试。

各层至少携带：对象/任务 ID、环境版本、任务计划版本、有效时间、记录/观测时间、来源与证据引用、信息类型、情景 ID、规则版本和适用范围。事实、记录断言、预测、情景假设和未知状态分别存储。

计划结束时间只是记录字段；未确认完成时不得自动解除活动约束。确认作业结束也不等于设施已拆除。预测不能覆盖事实记录。

## 1. 城市施工时空世界建模与演化推演

### 1.1 几何模型与语义场景图融合表达

建立园区、建筑、地面起降点、施工设施和作业活动的几何对象。初期采用盒体、圆柱、线段或多边形拉伸体，之后按需要接入更细三维模型。拓扑与渲染网格不替代碰撞几何。

语义图表达 `位于`、`属于`、`执行作业`、`影响范围`、`由记录支持` 等关系，关联设施参数、作业时段及变更来源。保留历史版本，支持按某个时点查询“当时已知的信息”。

### 1.2 多模态信息解析与智能体辅助更新

VLM/LLM 将施工文本、图片、视频关键帧中的可获取信息提取成结构化候选字段，并附证据位置。Agent 负责查询、字段校验、实体匹配、补证和更新工作流。

无尺度或定位依据的单张图片不能直接产生可靠米制高度、活动半径或地理坐标。信息缺失保留空值或区间；模型自报置信度不能当成已校准概率。更新需要通过类型、单位、时间和对象一致性校验。

初期先提供结构化记录导入，保留真实模型适配器。API 未配置时返回明确的不可用状态；不将预填结果包装成模型识别输出。系统不通过大模型直接控制飞行器。

### 1.3 施工设施与作业活动参数化

设施包含基座位置、塔身高度、臂长、臂体厚度、回转角及停放姿态等参数；活动包含作业类型、允许回转范围、载荷活动范围、开始时间、计划结束时间及完成确认。

分别表达永久/持续物理占用和随作业时段变化的活动占用。参数有来源、有效期和不确定性描述；设施拆除作为单独事件处理。

### 1.4 规则约束与多情景施工演化推演

首版世界模型是可执行的状态转移与占用推演：

`S_predicted(t+τ, k) = F_rule(S_known(t), work_plan, scenario_k, τ)`。

按设备运动规则、施工状态机和时间条件生成按期、延期、未确认等情景。明确情景假设，不为没有统计依据的情景随意赋发生概率。

后续在有时间对齐的历史视频、设备记录和施工日志时，训练活动范围、阶段变化或延期预测模块，替换部分规则预测。保留规则范围约束、数据适用条件和模型版本，不要求从头训练通用视频世界模型。

### 1.5 事件驱动更新与输出

变化事件记录对象 ID、变化前后字段、有效时间、证据、旧/新环境版本和受影响范围。只重算关联状态与下游结果，保留事件日志。

补证得到的新信息先校验，再作为新的来源记录进入第一层；无回答不代表已完成作业。第一层输出版本化场景快照、情景轨迹或时空占用描述、变化事件与信息缺口。

## 2. 动态时空约束与智能冲突分析

### 2.1 施工语义规则映射与动态时空约束

把对象、设施状态和活动映射为电子围栏、物理占用、活动占用及保护范围。规则须可追溯：

- 新增设施/尺寸变化：更新物理占用。
- 作业开始、暂停或活动范围变化：更新活动占用；暂停不自动等同于全部风险消失。
- 已确认完成：结束相应活动占用，重新计算设施停放几何，仍保留物理设施。
- 已验证拆除：按拆除有效时间解除对应设施约束。
- 计划到期但未确认：保持未知状态，采用已声明的保守边界或延期情景。

飞行器和障碍物保护范围需明确包含哪些定位误差、尺寸、建模误差与业务余量，避免同一误差重复膨胀。几何保护参数是可配置设计假设，不宣称为已核实的法规数值。

不确定性可以先以来源区间和多情景传播；后续以分位数回归和独立残差进行共形校准等方法估计范围。记录校准样本量、适用分布及覆盖假设；没有数据时标为未校准。位置/高度范围覆盖率不等同于飞行安全概率，也不能直接推导整条路径的联合覆盖率。

### 2.2 候选关联构建

利用时段、包围盒和空间索引进行保守筛选，建立任务与施工约束的候选关系。筛选需考虑保护范围及不确定性外包络；只有在满足已声明条件时才能剔除不相关项。

### 2.3 基于 XGBoost 的冲突敏感性学习

以“任务—约束”对为样本，输入距离、时间重叠、净空、参数缺失、来源时效和情景差异等决策时已知特征。输出精算优先级或补证敏感性排序。

可用仿真精算的冲突标签、参数扰动后判断变化和条件情景冲突比例构造训练目标；这些不是实际事故概率。模型仅调整处理顺序，低分不能跳过必须完成的约束检查。

### 2.4 基于图神经网络的多任务关联

基于任务—约束关系及共享成因构建图，学习任务影响程度、联合复核或联合修复优先级。没有训练数据时使用显式连通关系或规则排序，并标明 GNN 未训练。

训练样本按完整园区/施工事件分组，避免同一事件片段跨训练集和测试集。下游模型使用上游分数时采用折外预测或其他防泄漏机制，不能用对本样本过拟合的分数构造虚高结果。

### 2.5 时空冲突精算与证据

比较同一时刻的飞行器保护体和施工占用体，检查静态设施、活动范围、动态障碍及边界。采用连续航段/扫掠体检查，或带保守误差界的近似；不能只检查离散航点而漏掉中间穿越。

输出冲突任务、航段、对象、起止时段、几何位置、约束原因、情景、输入版本、证据引用及已完成检查范围。分别说明物理交叉、活动占用和保护余量触发的冲突。未覆盖或超时的项记为未检查，不记为无冲突。

### 2.6 冲突驱动主动补证与增量复核

从影响判断的未知字段出发，估计补齐字段可能带来的判断变化，生成有预算和截止时间的补证请求。请求可查询已有记录、在线来源、用户上传材料或明确标注的仿真证据服务。

补证请求包含：来源层、目标对象/字段、相关任务、所需证据、可能影响、截止时间和当前版本。统一走第一层校验更新，再重新生成约束与结果。不得直接读取仿真未来真值冒充实时补证。

### 2.7 输出与规划反馈接口

第二层既检查原有任务，也检查第三层提交的候选路径、出发时间和联合计划。候选绕行可能引入新的对象、任务和资源关联，复核不能限定在原冲突列表。

结果包含冲突状态、适用情景、检查范围、未解决信息、环境/计划版本及检查完成度。第三层可发起基于维护决策价值的补证，沿用同一个证据工作流。

## 3. 学习引导的时空规划与协同任务维护

### 3.1 面向既有任务维护的航路图

建立航点、航段、起降/等待点与共享资源。边记录长度、通行时间、方向与资源代价，任务记录必达服务点、服务时间/顺序、时间窗、优先级及飞行器资源约束。

首版固定任务—飞行器分配及基本速度模型，局部修复受影响计划。保留原计划版本并计算路径、时间和任务变动，不能通过删除必达巡检点制造可行路径。

### 3.2 学习排序选择修复候选

候选可表示为“任务子集＋延后/绕行/局部重规划动作＋搜索区域和时间范围”。以 XGBoost 排序模型等学习在给定搜索预算下哪些候选更可能得到合格、代价较低且稳定的方案。

排序发生在昂贵求解之前；对已完整求解的方案直接使用实际约束结果与代价比较。学习输入只能来自决策时已知信息。未训练时采用明确规则排序，保留可替换接口。

### 3.3 安全时间区间候选搜索

以 SIPP（安全时间区间路径规划）表示航点在给定占用约束下的可用时间段。扩展时同时检查整段边的通过时段和连续空间冲突，不能只看起终点是否可用。

等待优先选择地面起降点；空中等待需要单独验证空间占用、动力条件和能耗。首版可在固定速度等明确假设下生成多个候选，并独立检查能耗与任务条件。

如果将能耗等资源纳入搜索状态，需要处理多标签和支配关系；不得在增加资源约束、学习排序和预算截断后照搬原算法的最优性或完备性保证。找不到结果应区分超时、预算耗尽、信息不足和已证明不可行。

### 3.4 多任务修复与稳定性优化

首版采用优先级规划、时空预约表、有限次优先级重排和回溯。检查迎面、交叉和同向保护距离、共享起降/等待资源以及同一飞行器任务衔接。

修复集合从受影响任务开始，若新航路影响原本无冲突的任务，则扩展集合后再次求解。已有预约必须基于一致版本，不能将候选预约提前覆盖现行计划。

先满足已声明的硬约束与任务要求，再比较重要任务完成、变更任务数、时间偏移、绕行距离、能耗和再次调整风险。可采用字典序或显式权重，记录其配置；不能用较低代价抵消硬约束冲突。

后续可探索以图关系引导联合修复或大邻域搜索，不将尚未实现的学习增强写成已完成功能。

### 3.5 面向维护决策的主动补证

比较不确定字段取不同值时，“延后、绕行、保留或暂缓”的推荐是否改变，优先请求可能改变选择的信息。没有可信概率时用情景比较或稳健分析，不杜撰期望收益。

补证有截止时间和成本上限。等待证据时必须有经检查的暂缓/地面等待方案或明确标示无法继续；不能依赖尚未收到的确认提前执行。

### 3.6 滚动维护与条件化结果

按新增施工信息、作业延期、补证结果、任务进度/偏差等事件滚动更新。对未受影响任务尽量保持计划稳定；窗口、频率与计算预算可配置。

输出维护候选、变化原因、任务变更、适用情景、未解信息、资源代价、环境与计划版本、检查范围及有效时域。相关输入发生变化时标记待复核。

候选经过第二层及独立资源/任务检查后，仍需用户采纳才成为当前计划；采纳时再次校验版本，一致后原子更新计划与预约表。未检查、过期、未知或冲突的候选不能覆盖现行计划。现行计划受新事件影响时标为待复核，保留历史。

### 3.7 仿真训练与学习

先由确定性引擎产生可复现的情景和求解记录，再训练敏感性模型、GNN 和修复排序模型。高预算求解结果作为参考，不在未证明时称为全局最优真值。

完整事件/布局分组划分训练、校准、验证和测试；保存随机种子、场景参数、模型版本。禁止使用未来实际结束时间、隐藏情景分支或事后修复结果作为在线输入。记录失败/超时原因，不把全部失败标为不可行。

## 4. 集成与验证安排（对应后续 3.3，而非新增算法层）

开发阶段可用少量合成场景验证接口；有学习数据后再开展训练和效果评估。关键检查包括：未确认完成不释放占用、设施仍存在、边穿越检测、版本失效、未知结果不被当成通过、补证预算终止、候选不自动采纳、绕行引入新冲突后的再次分析。

仿真隐藏真值应与决策可见状态分开，按观测时间释放信息。使用独立参考几何检查器或手工可核算场景验证关键边界，不仅用同一实现反复证明自身正确。

对照方案包括规则排序、无学习的时空规划、整批重规划及关闭补证的版本。指标可覆盖约束违规、漏检、未检查比例、任务完成率、延误、路径/能耗代价、变更任务数、再次改动次数、计算时间及补证成本。所有数值必须来自实际运行，未运行只列待测指标。

初期合成数据和简化运动模型支持软件原型验证，不代表真实施工预测精度或飞行运行安全已得到验证。
