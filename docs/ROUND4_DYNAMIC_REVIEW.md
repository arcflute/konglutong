# 第四轮动态规划独立代码审查记录

审查范围：`motion.py`、`temporal_windows.py`、`planning.py`、`geometry.py`、`reference_geometry.py`，以及新增单实例恢复的`recovery.py`、`storage.py`、`web.py`和`execution.restore_full_task`。本文件记录代码与可核算案例的审阅，不是形式化证明或现场认证。

## 窗口保守性

时间管在片中点几何上加`VΔt/2`，包含该片内连续物理部件。对任意真实碰撞，航段空间参数必须位于该管的相交区间`[u0,u1]`，碰撞时刻必须位于管的时间片`[a,b]`；因此出发时刻属于`[a−u1T,b−u0T]`。禁止所有这样的出发时刻，能覆盖两次节点采样之间的穿越。取多条约束并集也不会把一条持续禁入规则解除。

支持几何的膨胀关系分别是AABB与保护球的距离关系、胶囊半径相加，以及圆柱径向/轴向同时扩张的保守外包络。包围盒筛选包含相同膨胀参数，因此不能因先筛掉保护边界而放行。时间片压缩只合并相同固定几何与相同膨胀量的相邻片，不改变管的覆盖。

主分析器和规划的时间片锚点可能不同。首个等待试验确实出现“规划已找到、主检查保守边缘误报、独立参考无冲突”，随后加入明确的`2×主检查最大切片膨胀`规划余量；没有删除冲突或减小保护半径。数值参考仍可能在极接近边界时保守拒绝，最终候选必须通过它。

## 误差、暂停和停车

暂停/恢复平移程序相位并保持连续姿态，已知完成姿态到已知停车目标按速度界连续变化，因此位置误差加`V×clock_s`覆盖同一模型段内的相位偏差。未知程序外姿态或未知停车目标不使用有利姿态，而用完整范围；程序、命令及相位误差前后边界参与时间切分。

`clock_s`只表示设备程序相位误差，不表示设施尺寸/基点/参数更新记录的有效时刻不确定。新参数模型在明确有效时刻分段。若记录的生效时刻本身有范围，需要额外的多时序情景或扩大占用区间；当前没有自动推断该范围。信息到达时间仍控制何时可见，不能把未来命令提前导入。

传统round3模型没有误差字段时，分析结果仍是确定性规则条件下的结论；动态搜索不会因此启用精确时隙，而逐约束退回完整范围。零误差必须显式声明来源，合成零误差不能解释为真实测量精度。

## 在途与资源

动态专项实际检查了8秒正在飞行的任务：冻结前缀到`(20,60,10)`，候选从该位置继续且独立复核通过。地面等待期间重新维护的`restore_full_task`必须从拼接后的完整轨迹重新计算实际起飞和等待元数据；评估阶段已定位旧逻辑沿用原元数据的错误，由评估模块负责人修复。建议保留“恰好首次上升起点”和“上升途中”两个边界，前者可变更未来起飞，后者不得变更历史起飞。

起降点容量与物理分离是两项不同约束。节点安全区间原来将任一pad预约当成容量已满，本轮改为按容量计数；同位置保护体相撞仍会阻挡，容量2不意味着两架飞行器可以重叠。

## 恢复审查发现与移交

发现`SimulationApp._session`在验证场景checkpoint前将session写入缓存：若某个SQLite的绑定不匹配，第一次请求拒绝后缓存仍留着未验证session，第二次请求可能绕过该场景绑定验证。已将具体路径移交恢复负责人，要求验证成功后再缓存或异常时清除，不在本审查中覆盖对方文件。

发现`PlanStore`旧预约表只保存`pad_reservations`，没有保存具名等待区和同机周转驻留预约。完整任务足以重新算出这些预约，但不能把原表称为完整资源预约恢复。已移交恢复负责人统一持久化完整联合预约并做恢复核对。

候选采纳仍会核对环境、任务计划、预约、模型、规则和情景版本，重新生成所有约束并独立复核；未发现正常恢复后直接跳过这些检查的路径。绑定输入文件/模型工件/运行源码的内容哈希与单实例锁提供保守拒绝策略，变更代码需新实验目录或明确匹配旧版本，而不是默默把旧结果标为同一计算。
