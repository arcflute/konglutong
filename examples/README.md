# 合成园区示例

`park_crane_synthetic.json` 为人工构造的小型输入，不含真实地理位置、施工单位或实际飞行记录。原始JSON中的检查点保留为输入说明；首轮已实现解析/计算入口，实际执行证据见 `../docs/VALIDATION.md`，不将预期字段本身视为测试结果。

## 场景内容

- 一个平坦局部坐标园区、一栋建筑、四个地面起降点。
- 一台已有塔吊，塔身和固定停放臂杆为物理占用；新增吊装活动另有简化圆柱外包络。
- 三架飞行器分别执行三项任务。前两项在不同时间通过相同巡检航线，第三项在空间上远离吊装区。
- 正常确认结束、收到延期记录、结束仍未确认三条情景分支。

坐标为米制局部 x/y/z，z=0 是合成平坦地面，不是海拔。所有时间为从虚构 t0 起的秒数。轨迹相邻点之间分段线性插值；重复位置的不同时间点代表停留。服务点、服务时长、飞行器标识、起降点和资源条件须保留。

## 初始可见信息

`observed_snapshot` 表示 t=60 秒时已知的状态。施工计划为 [120,360)，结束尚未确认。

`scenario_definitions_for_simulator_only` 是仿真驱动程序的分支配置，不能直接交给在线规划器作为已知未来。仿真器按 `observed_at_s` 释放事件；在线服务只接收当前快照与已释放事件。离线可以分别在显式情景假设下推演，但输出必须标明假设。

各分支没有发生概率。`end_unconfirmed` 的 900 秒是示例计算时域，不是预测的真实结束时间；到 900 秒仍不能自行判定作业结束。

## 实现约定

首版可以先支持盒体、圆柱及胶囊体；若暂不支持某种几何，需提供保守外包络并说明近似，或显式返回不支持，不能静默忽略。保护体与活动外包络的误差语义应在数据契约中说明。

示例提供的 `protection_radius_m`、能耗容量和消耗系数是设计用合成参数，不代表法规限值或设备测量。需要计算飞行和悬停消耗、地面等待、降落余量及任务期限。模拟地面零等待消耗只是这里的简化假设。

任务 1 应受到吊装活动影响。任务 2 是否受影响取决于到决策时已收到的证据以及声明的情景假设。任务 3 的对照作用仅是验证对该吊装活动的空间筛选，不说明整个任务无需任何检查。

该文件适合联调，不构成学习算法训练集或校准集。后续需要生成多种布局、设备参数和完整事件序列，并隔离训练、校准与测试数据。

## 起降点与等待资源

每个起降点容量为 1，约束起飞、降落及明确选择在该点发生的地面等待。原轨迹只描述任务出发后的占用，不表示所有飞行器从 t=60 起就已经同时停在该点。若维护方案延后起飞，需要明确任务开始前的待命位置、进入起降点的安排，或将等待计入该起降点预约并处理容量冲突。不能只平移轨迹时间而忽略等待资源。未建模的准备阶段应作为结果条件说明。


## 首轮实际运行

在项目根目录执行 `.venv/bin/chengkong demo --output runs/demo`，得到三情景×四时刻共12份JSON快照及summary。60秒的未确认状态下，任务1和2均与活动相交，任务3对该活动无冲突；绕行候选保留服务和全部任务并通过独立复核。按期分支360秒确认完成后，任务2与该活动无冲突；延期600秒确认仍不会抹掉任务2在395.7—408.3秒已发生的历史轨迹冲突。设备物理包络始终保留，除非单独确认拆除。

后续时刻的输入仍为原始计划历史，不假装任务曾自动采纳60秒的候选。已启动的受影响任务只提示人工运行复核，在途重规划待实现。任务/约束状态为相应检查范围内的结果，整体任务条件另见`baseline_full_review`；`clear`不表示现实运行安全认证。
